# Checked high-level VI identity owner: implemented contract

Scratch-only scope: new GuestVI.c/h, exact-entry GuestVIDispatch.c/h, original synthetic tests and reproducible recipe/locks. No canonical Process/App/CPU edits, original function invocation or further game inspection. Existing NVN composites stay byte-identical. The metadata-only result establishes a candidate main import chain, not observed execution.

## Identity reservation (required trusted Process integration)

Caller reserves a dedicated page-aligned4KiB guest virtual range with an actual4KiB backing initially RW, reprotected to NONE before the Process is published. Process rejects all guest mapping/reprotection/resize/replacement/alias operations involving the range. This is Process-enforced permanence, NOT CPU-intrinsic immutable provenance: privileged host CPU APIs can still mutate the range, and per-call validation must detect/refuse such changes. No executable/writable alias is admitted. It counts against the existing Process memory/map limits. The owner does not allocate/map this range or claim its bytes are a retail Display/Layer/NativeWindow representation. It issues distinct16-byte-aligned addresses from a monotonic never-reused cursor (256 total identities per owner lifetime); no host pointer or native surface token enters guest RAM. No generation wrap/address reuse: exhaustion stops honestly. A new process owner must use a genuinely new process/reservation generation and cannot coexist with an older owner for that same reservation.

Config carries process generation, reservation generation/base/size and explicitly attached App surface epoch, all trusted host data. A required pure, borrowed per-call reservation validator attests that the stopped CPU belongs to this configured process and the actual reserved backing remains protected. Failure to read via check_range is NOT proof of NONE permission; the validator must inspect authoritative Process mapping/provenance. Original tests create a concrete dedicated RW region, reprotected to NONE before publishing their synthetic Process fixture. They explicitly verify validator refusal after privileged host permission/mapping mutation. Output checks also require physical disjointness against the complete reserved backing, preventing an alias from overwriting identities. No callback/context/CPU is retained past dispatch. Cleanup needs only owned metadata/reference counts.

Unknown SDK code that dereferences an identity faults on the protected mapping, rather than receiving fabricated fields. This is deliberate narrow API ownership, not opaque retail-layout compatibility. Before canonical integration, root must supply/enforce that Process reservation and precise unsupported-consumer diagnostic. A real high-level boundary must eventually account for any initialization/alternate API actually reached.

## One-display/one-layer profile and real owned state

Owner states ACTIVE/DETACHED/RETIRING. One live Display, one child Layer and one stable NativeWindow identity per Layer. No display/layer dimensions, refresh rate, crop, scaling, present policy or retail defaults are fabricated. Basic CreateLayer has unspecified extents; later actual admitted Window textures can supply extents. Sized/settings overload entrypoints are explicitly recognized but return host UNSUPPORTED without changing guest state; exact settings layout remains unknown.

- OpenDefaultDisplay: requires active attached surface, no live display, and available identity slot. Commits a new Display identity and writes it to the checked Display** only after complete validation. Duplicate open stops RESOURCE_BUSY; this limited profile does not invent open-reference semantics.
- Basic CreateLayer: validates exact live Display identity/generation and no live Layer, reserves a new identity, then atomically commits Layer** and parent-child metadata.
- GetNativeWindow: validates live Layer and attached same epoch; first success creates a stable NativeWindow identity, repeated success returns that same owned identity. No guessed surface pointer or callback executes in guest context.
- DestroyLayer: refuses while future Window references exist; otherwise removes native/layer identities without guest-object writes. Stale identities never become valid again.
- CloseDisplay: refuses while a Layer exists; otherwise removes Display. No invented nn::Result error codes: unsupported/invalid/busy cases are explicit host stops with unchanged guest registers/memory/PC. Only real successful Result-returning operations set W0=0; the two void operations preserve X0.

Native identity resolver/retain returns copied host-only metadata (process/reservation generation, display/layer/native identity generations, epoch), plus a private bounded generation reference. Future WindowInitialize retains it before committing, WindowFinalize releases it. At most32 references; no host ref token enters guest RAM. Retains prohibit layer destruction and display closure transitively. A host detach invalidates new opens/creates/native resolution; existing references remain releasable. CPU-free retirement rejects new work, retains all metadata until references release, and then destroys the owner. No silent dangling window identity.

## Interpreter entry adapter and transaction

Resolve exact seven public names through existing GuestSymbols against bounded actual module tables. Five operations are supported; both other CreateLayer overloads are recognized as unsupported. Require unique valid global/weak function definition with valid visibility/full aligned executable text span, reject ambiguity/malformed tables. Defined-only metadata from the prior study is not this validation. Return breakpoint addresses for the caller to MERGE with the existing NVN set (≤32 total); never replace unrelated registrations, patch NSOs or install native callbacks. Optional absent teardown/unsupported overload symbols need explicit resolver policy, not guessed offsets.

The handler validates a fresh CPU BREAKPOINT and current stopped PC; the operation is chosen solely by that exact registered PC. Copy register arguments to local values, validate current owner/reservation/epoch and LR, check the8-byte output range and required pure protected-range guard against other live emulator objects/storage. The complete reserved backing participates in physical alias checks. No guest-controlled byte is interpreted as a native pointer.

All candidate state is assembled without publication. The last pure cancellation/deadline check precedes commit. Set/validate guest PC to LR before the one checked atomic writev; failure restores the original trap PC. After write succeeds, commit fixed owner metadata and set W0 success with no allocations/callbacks/fallible cleanup remaining. Stopped-context exclusivity guarantees the register update; unexpected internal mutation failure is a terminal invariant failure, not a retryable refusal. For void destruction, LR validation precedes the metadata-only commit and X0 remains unchanged. All ordinary refusals preserve guest bytes/registers/PC, live identities, cursor and reference counts. Diagnostic attempt/budget counters, if exposed, are explicitly separate from semantic state and may count refusals, matching existing dispatcher limits.

Caller serializes Process, owner, reference operations and any graphics-window adapter. Global try-gate rejects reentry; cancellation and guard callbacks cannot run guest code or mutate owner/CPU/mapping state. A cumulative lifetime event budget and a fresh per-dispatch monotonic deadline remain mandatory because breakpoint events can cost zero interpreted instructions. No borrowed CPU/provider pointers survive any return or retirement.

## Required original-fixture gate before release

1. Actual checked symbol tables and independently encoded BL/BLR call fixtures execute the five operations and verify outputs, W0/void preservation, LR, exact definition routing and unsupported overload refusal. No original game body in fixtures.
2. Open/create/get identity stability; failed/repeated open and wrong-parent/stale identity; destroy/close and recreate allocate different identities; lifetime256 exhaustion preserves output/state.
3. Writable output full span, invalid LR, prefix/suffix guards, physical aliases against reserved/foreign protected ranges, missing/mismatched reservation and process generation, mutation/reentry/cancellation failures preserve all semantic state.
4. Future Window reference retain/release concretely prevents DestroyLayer/CloseDisplay and CPU-free teardown; detach makes stale epochs refuse, live references drain without CPU/callback.
5. Existing GuestSymbols malformed/ambiguous/undefined resolution policy and merged breakpoint ownership. CPU backing/accounting is released only by the actual Process fixture after the VI owner is drained.

This produces a real bounded identity graph on the evidenced high-level ABI. It does not implement VI Binder, NVN Window/Acquire/Present, guessed SDK object layout, rendering or displayed game frames. Actual integration remains gated on Process reservation and real interpreted call observation.

## Chosen construction and trusted lifetime boundary

Parent selected B: preserve current CPU API/gates. Package agent owns a separate concrete Process reservation implementation/validator. Creation is RW→NONE before publication, charged4KiB and one region. Runtime validator checks authoritative Process reservation identity, same process/shared CPU, exact current coverage/permissions/backing/exclusivity and protected range policy. Host check_range read failure alone is insufficient. Trusted host mutation must produce a refusal; CPU APIs do not promise this range is intrinsically immutable.

One VI owner is created at most once per live Process reservation. Destroying the C owner is terminal for that reservation while the Process still exists: root must not recreate a cursor at the same addresses. The Process attachment/claim must enforce this once-only lifetime; new surface epochs do not reset identity issuance. The initial profile uses terminal detach/retirement rather than speculative reattachment semantics. The C owner can be fully freed only after reference drain, then its Process reservation remains reserved until Process destruction. A fresh Process generation may have its own namespace. This closes stale-address reuse across owner recreation, not just across DestroyLayer/CreateLayer.

## Implemented C contract

- `SatchelGuestVIConfig`: version/size, process_generation, reservation_generation, identity_base, identity_size, surface_epoch. Nonzero host generations/epoch; exactly aligned4KiB range. No dimensions/default flags/native pointers.
- `SatchelGuestVIBorrow`: stopped `SatchelCPUProbe*`, required reservation-validation callback/context, required protected-output-range callback/context, optional pure cancellation callback/context. Every pointer/context is borrowed for one call only; none is stored by owner or reference.
- `satchel_guest_vi_create(config, cpu, claim, context, &owner)`: bounded host allocation and preflight precede the borrowed constructor-only one-way Process claim. Config is copied first; no fallible work follows a successful claim before publication. It creates no Display/Layer and no output identity. A failed claim does not publish an owner.
- `satchel_guest_vi_execute(owner, borrow, operation, x0, x1, trap_pc, return_pc, &result)`: five operation enum entries. Common complete validation/transaction outlined above. Result is host metadata only; five operations use exact declared ABI. No guest error-code fabrication. Ordinary host refusal preserves all semantic owner state and guest bytes/registers/PC. Exact adapter, not arbitrary guest input, supplies the operation.
- `satchel_guest_vi_retain_native(owner, borrow, native_identity, &reference, &info)` / `release_native(owner, reference)`: host-only bounded references for future NVN Window ownership. Info copies exact configured generations/epoch and live identity generations; no dimensions/retail fields. Retain validates current reservation and active epoch, publishes outputs together; release is CPU-free and stale/duplicate release refuses.
- `satchel_guest_vi_detach(owner, epoch)`: exact epoch only, terminally blocks new open/create/get/retain. Existing close/destroy/release and CPU-free retirement still work; no implicit new surface.
- `satchel_guest_vi_try_destroy(&owner)`: marks retiring; returns BUSY and preserves pointer while references exist. Once empty, drops Layer/Display metadata and frees without CPU/context/guest writes. Process retains the identity reservation through its own teardown.
- `satchel_guest_vi_stats(owner, &stats)`: copied host counters for live Display/Layer/Native/reference/issued identities; used by original lifecycle tests. No host pointers or original bytes.
- `satchel_guest_vi_resolve_entries(tables, count, read, cancelled, context, timeout_ms, &entries)`: copied exact-name table, using GuestSymbols. OpenDefaultDisplay/basicCreateLayer/GetNativeWindow must each have one valid definition. Destroy/Close and sized/settings definitions are optional but, if present, must be unique valid executable functions; ambiguity/malformed/incompatible symbols refuse the entire table. Missing optional entries stay absent, never invented offsets. Seven names maximum; resolver deadline must be 1–1000 ms.
- `satchel_guest_vi_dispatch(entries, owner, borrow, fresh_stop, &report)`: validates actual stopped PC through zero-budget CPU observation, chooses exact operation, returns NOT_OURS for other PCs, explicit UNSUPPORTED for sized/settings entries. Five supported handlers use x0/x1 and LR; no original body invocation. Caller merges returned entry addresses with existing NVN breakpoints and preserves bounded aggregate event/deadline accounting.

All output pointers have explicit failure behavior, natural alignment checks and exact version/size where appropriate. Actual callable-entry lookup still needs complete metadata validation; prior nonzero-shndx classification is not reused as an authorization shortcut. Reference count and guest identity namespace generations never wrap; exhaustion refuses without consuming an identity.
